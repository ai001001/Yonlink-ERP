- 首跑 41 条，38 通过、3 失败。分析：
  - **T1（用例问题）**：TC-SS-02 期望业务员「未核验转正」返回 409，实际 403。系统先校验权限（业务员无样品新增权）再校验状态，属正确行为；改为用经理账号验证状态拦截。

# V4 安全加固测试报告

测试日期：2026-11-05　**结果：81/81 自动化用例通过（新增 11 条安全用例）；6 个岗位 × 38 页面在 CSP 下 0 违规 0 错误；在线演示版在 CSP 下正常运行。**

## 加固内容
1. **密码**：12 个演示账号改为各不相同的复杂密码；强密码策略在新建/重置/修改时强制；重置改为系统生成一次性临时密码；首次登录与弱密码登录强制改密；改密后其它会话失效。
2. **演示账号表格**：登录页以“岗位 / 账号 / 密码 / 填入”表格展示，可在系统参数关闭；改过密码的账号不再展示；管理员工作台提示关闭展示与修改密码。
3. **防暴力破解**：账号连续 5 次错误锁定 15 分钟、IP 级失败限流、管理员解锁、不泄露账号是否存在、固定时间比对。
4. **网站加固**：CSP 与全部安全响应头、去除所有内联脚本、防嵌入（静态托管用脚本兜底）、令牌不入网址、错误不泄露内部信息、静态文件防穿越、防慢速攻击、请求限流、下载沙箱、邮箱 SSRF 防护、系统参数白名单。

## 测试中发现并修复的问题
| 编号 | 现象 | 严重度 | 修复 |
|---|---|---|---|
| P1 | 退出登录后上一位用户的页面内容仍留在网页中，下一位用户登录时（改密窗口背后）可看到管理员的账号列表 | 严重（信息泄露） | 退出时清空页面内容、菜单、弹窗与打印区 |
| P2 | 请求限流按 IP 计算，同一办公室共用出口 IP（或经反向代理）时可能整体被限流 | 一般 | 登录后按账号限流，匿名请求才按 IP |
| P3 | 登录失败计数为进程级共享，多个实例互相影响 | 一般 | 计数器改为每个应用实例独立 |
